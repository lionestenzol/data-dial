## Verdict

- **No new mathematics or information theory is required** for most practical
  forms of the GIR objective. Humanity already has: side-information coding,
  differential reconstruction, content-addressed reuse, deterministic
  recomputation, cache lookup, set reconciliation, convergent replication,
  named computation, shared-codebook activation, and (weaker equivalence)
  semantic/generative reconstruction.
- **Stopping Condition C/D, not A or B.** No single existing system is a
  complete universal solution (A), and no single one is configurable to the
  full objective (B) — though Nix/Bazel come close for software artifacts.
  Existing mechanisms **integrate** to cover most of the capability (C), and the
  **specific residual gap** (D) is a *general, cross-information-type
  mechanism-selection layer* that chooses among transfer / delta / recompute /
  cache / generate / sync / activate under one cost objective and a declared
  equivalence standard.
- **The irreducible boundary (E).** For an arbitrary N-bit target that is both
  previously unseen AND unpredictable from B's state, at least N bits of
  distinguishing information must enter B. Relabeling the signal a clock state,
  hash, residue tuple, coordinate, or function call does not change the counting
  bound. This is `K(X|K_B)` / communication-complexity, not an engineering
  shortcoming. Conventional transfer must remain the universal fallback.

## Scientific capability map (established mechanisms)

| family | established name | capability | key limitation | source |
|---|---|---|---|---|
| statistical coding | source/entropy coding | compact representation from source statistics | cannot beat entropy by renotation | Shannon 1948 |
| lossless w/ correlated side info | **Slepian–Wolf** (1973) | separate encoders, joint lossless decode near joint entropy | needs exploitable correlation | SW 1973 |
| lossy w/ decoder side info | **Wyner–Ziv** (1976) | decoder prior lowers rate at a distortion | not exact bits | WZ 1976 |
| conditional algorithmic info | conditional Kolmogorov cx | "how much genuinely new description" given B's state | uncomputable; boundary tool only | Li/Vitányi |
| shared reference/codebook | dictionary / capability activation | short token selects large provisioned object/action | provisioning displaced not eliminated | — |
| differential reconstruction | **rsync**, RDC, content-defined chunking | reuse receiver blocks, send only unmatched | benefit falls with overlap | Tridgell–Mackerras 1996; MS-RDC |
| content-addressed reuse | CAS, Merkle DAG, CID | address/verify by digest | a digest is not a recipe for absent content | IPFS docs |
| deterministic recomputation | reproducible builds, Nix, Bazel | rebuild from recipe+inputs instead of transfer | compute may exceed transfer; hermeticity fragile | Nix/Bazel docs |
| cache-or-compute | memoization, action cache, REAPI | reuse if present else execute | scope = modeled actions | Bazel REAPI |
| set reconciliation | **IBLT**, sketches | recover small set differences without full retransmit | fails above difference capacity | Goodrich–Mitzenmacher 2011 |
| replicated-state convergence | **CRDTs** | replicas converge without one canonical byte stream | only defined CRDT semantics; not byte/history identity | Shapiro et al. 2011 |
| named content | ICN/CCN/NDN | request by name, reuse caches | missing content still transferred | Jacobson et al. 2009 |
| named computation | **NFN** | names resolve to data OR functions/computation; cache results | research maturity; trust/placement open | Tschudin–Sifalakis 2014 |
| channel simulation | reverse Shannon / channel synthesis | reproduce stochastic channel w/ shared randomness | reproduces distributions, not exact bytes | Bennett et al.; Cuff |
| constraint reconstruction | CSP/SAT/SMT, inverse | determine object from conditions | unique spec ≠ tractable recovery | — |
| combinatorial indexing | ranking/unranking | integer rank ↔ structured object | rank still ~log|S| bits | Myrvold–Ruskey 2001 |
| residue representation | RNS / CRT | identify integer via residues | rearranges info, no free compression | classical |
| semantic/generative | semantic communication | reconstruct meaning/perceptual output | no exactness guarantee | DL semantic-comm research |

Cross-cutting fact: **receiver-side prior state has informational value.** A
20-byte reference names a 10-GB object only because B (or shared infra) already
holds enough to resolve it. Provisioning, installed models, caches,
dictionaries, recipes and common randomness are part of the total information
budget, not free.

## Comparative architectures (closest existing selectors)

Nix: substitute-from-store **or** build-from-source. Bazel/REAPI: local output →
remote CAS cache → local/remote execution. Both are mature **mechanism
selectors** but only over build/action graphs. NFN is conceptually broadest
(name → data or computation) but a prototype. **No evaluated architecture
provides all mechanism classes under one general objective function** — the
identified residual gap.

## The six original concepts → established counterparts

| original | counterpart | disposition |
|---|---|---|
| recursive information spaces | grammars, ranking/unranking, procedural generation | integrate where domain is compactly generatable |
| mathematical clocks / direct state | random-access indexing, counter-based PRNGs, jump-ahead | indexing, **not** an info-theoretic shortcut |
| overlapping clocks / CRT | RNS, Chinese Remainder Theorem | use for arithmetic/addressing only |
| relative relationships | delta coding, relative coordinates | adopt as differential representation |
| intersecting constraints | CSP/SAT/SMT, syndrome decoding | integrate solvers; benchmark inversion cost |
| theoretical/unmaterialized space | lazy eval, generators, symbolic/generative | general principle, not proof of arbitrary-data compression |

"A tiny interface activates a large capability" is routine — **but only because
the large capability already exists accessible to the receiver.** The economic
opportunity is exploiting preexisting structure better, not assuming naming
creates missing information.

## Disposition (standing policy for the project)

1. **Reuse established mechanisms first** (rsync/RDC/casync for file deltas; CAS
   for immutable reuse; Nix/Bazel for recomputable artifacts; IBLT for set
   diffs; CRDTs for convergent state).
2. **Integrate only where necessary.**
3. **Benchmark before building a generalized selector** — the one plausible new
   systems component. Prove its discovery/selection overhead is below the
   savings it creates before writing it.
4. **Preserve conventional transfer as the universal fallback.**
5. **Document the arbitrary-unseen-information boundary as fundamental**, never
   as a missing feature.

## Required benchmark (P0, the next action)

Per representative information class, run full-transfer baseline vs applicable
alternatives under cold AND warm receiver state. Report: equivalence class,
target size, receiver overlap fraction, provisioning bytes/time, bytes each
direction, compute time, storage r/w, peak RAM, energy if measurable,
verification cost, cache-hit rate, failure/retry, p50/p95/p99 latency. For exact
audio: high-entropy PCM, related-version, deterministically-synthesized, and
cached-object workloads; cryptographic digest for exactness; perceptual metrics
only as a separate non-exact track. **Report the whole critical path, not the
final signal size** — reporting only signal size systematically overstates the
advantage of receiver-side reconstruction.

## Confidence

HIGH: receiver knowledge/structure/tolerated distortion can replace
transmission, but arbitrary exact info absent from B requires enough new
distinguishing information to enter B. HIGH: rsync/RDC/CAS/Nix/Bazel/set-recon/
CRDT are genuine reusable prior art. HIGH: no magic from recursive addressing /
clocks / CRT / intersection notation. MODERATE–HIGH: no deployed general
cross-type selector exists (strong domain-specific ones found; absence ≠
nonexistence). MODERATE: practical value of a new general selection layer —
unbenchmarked, hence P0.
