# Progressive-disclosure research protocol

Consult RESEARCH_INDEX.json, CAPABILITIES.md, and ARCHITECTURAL_GAPS.md before repeating searches. Retain already accepted evidence and revisit when a release, requirement or test result changes.

For each candidate: read README and architecture page; inspect manifest/license; inspect one example plus relevant interface; run a bounded existing example; inspect implementation only to resolve a concrete question. Search symbols before reading files. Do not ingest whole repositories.

Suggested initial reading budget (planning limits, not measured billing): 1–2k tokens for screening, an additional 2–4k for shortlisted interfaces, then stop and run an experiment. Expand only with a named unresolved question. These are flexible limits; correctness takes precedence.

Record exact package versions/commit IDs for experiments. This pass pinned installed package versions in requirements.lock.txt; unexecuted repositories are documented branch-level screens, not immutable audits. Log failures and actual results without changing preregistered predictions. No provider token-cost estimate was measured in this pass.
